# Deliverable 4 — Evidence Against Ratification

Same discipline as Deliverable 3: every item traces to `PROP-0001`
itself or to real, cited work since. Nothing here is invented to
balance the package artificially — where the case against is weaker
than the case for, that is stated as found, not padded.

## From `PROP-0001` itself — the document's own named unresolved questions

1. **No independent reviewer role exists for Discovery Lab's own
   investigation reports.** `PROP-0001`'s own text: "GDE has a
   Critical Reviewer; KOD has a Research Guardian; Discovery Lab
   currently has neither." The recommended Variant B's own Review /
   falsification stage is, by the document's own admission,
   self-classified — the report author is currently also the
   classifier.
2. **Whether receiving repositories will actually act on routed
   proposals is untested.** The document states this as an open
   assumption, not evidenced by any actual agreement from KOD, GDE,
   trust-engine, or project-memory's own maintainers.
3. **Whether trust-engine's specification-vs-implementation gap
   reflects healthy sequencing or a real drift problem is unresolved**
   and, per the document's own words, "cannot be resolved without
   asking trust-engine's own maintainers" — outside `PROP-0001`'s own
   scope to answer.
4. **Whether `discovery-lab` should be added to `project-memory`'s
   `PROJECT_REGISTRY.md` is explicitly deferred**, on the stated
   principle that "the registry should not change while a repository's
   mandate is still DRAFT" — meaning ratifying now is also what
   unblocks this deferred registry question, which cuts both ways: it
   is evidence that the current DRAFT state has a real, live cost, but
   also that the document itself treats "still DRAFT" as a stable,
   acceptable holding position, not an emergency.

## From work completed since — reasons for caution, not reasons the mandate is wrong

5. **Every review and validation of `discovery-lab`'s own work to date
   has been conducted by the same session that built the architecture
   under review.** `ARCH-001`'s `R4` and `EXEC-001`'s
   `5-REVIEWER-RECORD.md` both record this directly: even `EXEC-001`'s
   one real independent Knowledge Review used a memoryless-but-
   orchestrated Agent instance, not a genuinely separate reviewer.
   Ratifying a mandate whose own Variant B explicitly names "no
   independent reviewer" as an open gap, using a process that has not
   yet had a single genuinely independent review performed on it,
   compounds rather than resolves that specific weakness.
6. **The mandate has never been tested against a real "no" from an
   external maintainer.** All evidence in Deliverable 3 for the
   mandate's practical viability comes from `discovery-lab`'s own
   internal operation (`AG-002`/`AG-003`) — none of it involves an
   actual routed proposal being accepted, rejected, or ignored by KOD,
   GDE, trust-engine, or project-memory's own maintainers, because no
   such proposal has ever been routed. The evidence supports "the
   internal discipline works"; it does not yet support "the
   cross-repository proposal mechanism this mandate exists to enable
   actually functions."
7. **Deferring costs comparatively little, on the document's own
   terms.** `PROP-0001`'s own self-critique states the current design
   is "fully reversible... nothing is deleted or mutated outside
   discovery-lab itself" and that no recurring monitoring is scheduled.
   This means the case *for* urgency (per `ARCH-001`'s `R1`) rests
   specifically on the Role-freeze-before-mandate-ratification
   sequencing risk, not on any operational harm from the mandate
   remaining unratified a while longer — a genuine, if narrow,
   distinction worth the human decision-maker weighing directly.

## What this evidence does not show

None of the above shows Variant B is the wrong choice, or that any
specific provision is defective — the Adversarial Review already
tested the document for defects and found none requiring the core
decision reopened. What it shows is that several of the document's own
named assumptions remain genuinely untested, and that the ecosystem's
general self-review weakness (item 5) applies to this ratification
process too, not only to `discovery-lab`'s object-level work.
