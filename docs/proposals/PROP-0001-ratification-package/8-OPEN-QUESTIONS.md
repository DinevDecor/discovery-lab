# Deliverable 8 — Open Questions

Every open question either quoted from `PROP-0001`'s own
"Unresolved questions" section, or newly surfaced by this preparation
task. None are resolved here — resolving them would exceed this task's
scope ("не създавай нови предложения").

## From `PROP-0001` itself, verbatim in substance

1. No independent review role is defined for Discovery Lab's own
   investigation reports (GDE has a Critical Reviewer; KOD has a
   Research Guardian; Discovery Lab currently has neither).
2. Whether `discovery-lab` should be added as a row in
   `project-memory`'s `PROJECT_REGISTRY.md` is explicitly not decided
   by the source document — deferred until the mandate is no longer
   `DRAFT`.
3. Whether Variant A's asserted prototyping need is real cannot be
   resolved by the source document — only by an actual observed need
   arising, which has not happened yet.
4. Whether trust-engine's documentation-vs-implementation gap is
   healthy staged sequencing or a real drift problem is unresolved and
   would need trust-engine's own maintainers to answer.
5. Whether a receiving repository would actually act on a routed
   proposal is untested — `Ecosystem Health Review v0.1` is designed to
   start probing this but cannot answer it definitively on its own,
   and cannot run at all before a mandate is ratified.

## Surfaced by this preparation task, not previously named this way

6. **Which variant, specifically, is being ratified?** `PROP-0001`
   recommends Variant B but presents all three in full. A human
   ratification decision needs to specify which variant it accepts (if
   any) — "ratify `PROP-0001`" is ambiguous between "ratify the
   document's recommendation" and "ratify the mandate question,
   choosing a variant independently." This package assumes the former
   throughout (per Deliverable 6/7), since that is what the source
   document itself puts forward, but the choice is the ratifying
   human's to make, not pre-selected by this package.
7. **Does ratification also resolve `AG-002`/`AG-003`'s standing, or
   is that a separate decision?** `GOVERNANCE.md`'s `FROZEN` axis and
   `HIRING-LIFECYCLE-DRAFT.md`'s adoption axis are independent by
   design; `PROP-0001`'s ratification directly addresses only the
   mandate that authorizes `discovery-lab` itself, not the two Roles'
   own trust status. `Deliverable 6` treats the Role-freeze consequence
   as following automatically from mandate ratification; whether that
   inference is correct, or whether a separate explicit decision is
   needed for `AG-002`/`AG-003` specifically, is itself unresolved by
   `PROP-0001`'s own text.
8. **Timing relative to `G2`'s Unified Control Plane Specification.**
   `G2`'s output is itself `DRAFT — Candidate for Adoption`, awaiting a
   separate human decision. Whether `PROP-0001` and `G2`'s adoption
   should be decided together, in sequence, or entirely independently
   is not addressed by either document — both are ready for a decision
   on their own terms, but their relative sequencing is a judgment call
   this package does not make.

## What these open questions do not do

None of the eight blocks a ratification decision from being made. Item
1 and item 5 describe known, already-flagged weaknesses in Variant B's
own design, not defects that need fixing before a human can decide
whether to accept them as-is. Items 6–8 are scoping questions the
ratifying decision itself will settle, not prerequisites to it.
